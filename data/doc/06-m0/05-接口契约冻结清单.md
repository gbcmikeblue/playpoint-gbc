# 接口契约冻结清单（contract-v1.0）

> **冻结含义**：M0 结束时这 15 个接口的「路径 / 入参 / 出参字段名」不再单方面修改，改动必须走本文第 6 节的流程。
> 全量接口（45+）见 [04-backend/03-API接口契约.md](../04-backend/03-API接口契约.md)；本文只冻结 M0-M1 用到的第一批。
> 打 tag：`contract-v1.0`，Swagger 快照存 `doc/99-evidence/swagger-v1.0.json`。

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| Base | `/{env}-api.playpoint.xx/api/v1` |
| 响应包 | `{ code: 0, message: "ok", data, traceId }` |
| 鉴权 | `Authorization: Bearer <token>`；标 `public` 的不需要 |
| 分页 | `?cursor=&limit=20` → `{ list, nextCursor, hasMore }` |
| 时间 | ISO8601 带时区 `2026-10-18T18:00:00+08:00` |
| 金额 | 整数分 `priceCent` / `amountCent` |
| ID | string |
| 幂等 | 写接口支持 `Idempotency-Key` 头 |

## 2. 认证（2 个）

### 2.1 `POST /auth/login` — public
```json
// req
{ "code": "wx.login 返回的 code", "scene": "可选，分享场景值" }
// res.data
{ "token": "eyJ...", "refreshToken": "eyJ...", "isNew": true,
  "user": { "id": "u_...", "nickname": "微信用户", "avatarUrl": null, "hasProfile": false } }
```
- 首次登录自动建号；`isNew=true` 时前端引导完善资料。
- 错误：`2001` 微信 code 失效（前端重试一次 `wx.login`）。

### 2.2 `POST /auth/refresh` — public
```json
{ "refreshToken": "eyJ..." }  →  { "token": "eyJ...", "refreshToken": "eyJ..." }
```
- 刷新后旧 refreshToken 立即失效（轮换）。

## 3. 基础（3 个）

### 3.1 `GET /app/config` — public
```json

  "categories": [ { "id": "cat_hot", "name": "热门", "emoji": "🔥", "hot": true } ],
```

## 6. 模拟支付（3 个）

### 6.1 `POST /orders`
```json
{ "bizType": 1, "bizId": "a_1002", "signupId": "s_2" }
→ { "orderId": "o_1", "orderNo": "2610180001", "amountCent": 19900,
    "expireAt": "2026-10-18T10:03:00+08:00", "reused": false }
```
- 同一 `(bizType,bizId,user)` 存在待支付单时 `reused=true` 并返回原单。

### 6.2 `GET /orders/:id`
```json
{ "orderId": "o_1", "orderNo": "2610180001", "title": "已有10人-疗愈游戏局…",
  "coverUrl": "…", "sessionText": "10月18日 19:30", "poiName": "深圳万象天地",
  "amountCent": 19900, "discountCent": 0, "payableCent": 19900,
  "status": 0, "statusText": "待支付", "payChannel": "mock",
  "expireAt": "2026-10-18T10:03:00+08:00", "serverTime": "2026-10-18T09:48:00+08:00" }
```
- `serverTime` 必须返回，前端用它与 `expireAt` 算倒计时差，避免依赖本机时钟。

### 6.3 `POST /orders/:id/mock-pay`
```json
→ { "status": 1, "paidAt": "2026-10-18T09:48:30+08:00", "ticketId": "t_1" }
```
- 已支付重复调用也返回 `status:1`（幂等）；过期/取消返回 `7002`。

## 9. 错误码（M0 使用范围）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1001 | 参数错误 | toast `data.errors[0]` |
| 1003 | 频率超限 | toast "操作太频繁" |
| 2001 | 未登录/失效 | 静默续期 → 失败跳登录 |
| 3001 | 活动已满 | toast + 刷新详情 |
| 3002 | 重复报名 | 当作已报名，直接跳票夹 |
| 3003 | 活动已结束 | toast + 返回 |
| 7001 | 订单不存在/已支付 | 已支付跳结果页 |
| 7002 | 订单过期/取消 | 置灰 + 提示重新下单 |

## 10. Mock 约定（前端）

```
miniprogram/mock/
├── index.ts          # 开关：config.env === 'dev' && storage.mock !== 'off'
├── feed.json         # 与 /home/feed 响应同构
├── activity.json
├── campaign.json
└── ticket.json
```

- **同构要求**：mock JSON 的字段名、层级、类型必须与接口响应完全一致，切真实接口时只改 `request.ts` 的 baseURL，不改任何页面代码。
- 列表 mock 至少 6 条，含 1 条 `priceCent > 0`、1 条 `full`、1 条无封面（测兜底）。
- `request.ts` 增加 `?mock=1` 调试开关，方便真机验证真实接口。

## 11. 类型生成

```bash
# 后端导出 OpenAPI
curl http://localhost:3000/docs-json -o openapi.json
# 前端生成类型
npx openapi-typescript openapi.json -o miniprogram/services/types/api.d.ts
```
- 生成物**入库**，CI 校验「重新生成后无 diff」，防止契约漂移。

## 12. 冻结后如何改契约

| 变更类型 | 流程 |
| --- | --- |
| 新增可选字段 | 后端直接加，通知前端，无需评审 |
| 新增必填字段 / 改字段名 | 提 issue → 双端评审 → 改文档 → 前端先兼容旧字段 → 两周后删除 |
| 删除字段 | 先标 `@deprecated` 保留两个版本，再删 |
| 改语义（如金额单位） | 禁止，只能新增字段 |

- 所有变更同步更新本文件与 `04-backend/03`，并在 commit message 标注 `contract:`。
