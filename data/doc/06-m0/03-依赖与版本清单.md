## 2. 容器（替代原 docker-compose 方案）

M0 只有两个容器，直接用命令管理，不引入 compose（Podman 的 compose 需要额外插件）。

```powershell
# 虚拟机（关机后需先启动）
podman machine start

# 首次创建（已创建则跳过）
podman run -d --name playpoint-pg --restart unless-stopped -p 5432:5432 `
  -e POSTGRES_USER=playpoint -e POSTGRES_PASSWORD=playpoint -e POSTGRES_DB=playpoint `
  docker.m.daocloud.io/library/postgres:15-alpine

podman run -d --name playpoint-redis --restart unless-stopped -p 6379:6379 `
  docker.m.daocloud.io/library/redis:7-alpine

# 日常
podman start playpoint-pg playpoint-redis
podman logs -f playpoint-pg
podman exec -it playpoint-pg psql -U playpoint -d playpoint
```

> `podman machine` 是 WSL 后端，容器端口会映射到 Windows 的 `localhost`，小程序与后端直接连 `localhost:5432` 即可。

## 3. 小程序端（`miniprogram/`）

### 3.1 运行时依赖：**无**

| 项 | 结论 |
| --- | --- |

## 5. 不引入的依赖（明确记录）

| 候选 | 不用的原因 |
| --- | --- |
| `tsx`（跑 Nest 入口） | 不支持 `emitDecoratorMetadata`，Nest 启动崩溃 |
| `mobx-miniprogram` | 需小程序 npm 构建；自写 store 零依赖 |
| `pnpm` | 全局 pnpm 绑在 Node 16，跨版本不可靠；统一用 npm |
| `docker` / `docker-compose` | 本机无 Docker，改用 Podman；两容器不值得引 compose 插件 |
| TDesign / Vant Weapp | 视觉高度定制，覆盖成本高于自写 |
| TypeORM | Prisma 的 migration 与类型生成更好用 |
| BullMQ / Kafka | 领域事件 + 定时任务足够，M0-M4 不需要 MQ |
| socket.io | 消息走 5s 轮询（已定） |
| axios / got | 小程序用 `wx.request`；后端用原生 fetch 调微信接口 |
| moment / lodash | 用 dayjs 与自写 `utils/` |

## 6. 版本锁定与升级

- `package.json` 内**不写 `^`**，全部精确版本；`package-lock.json` 入库。
- Node 版本靠 `.work/env.ps1` 前置 PATH，并在 `package.json` 的 `engines` 声明 `>=20`。
- 小程序基础库固定在 `project.config.json` 的 `libVersion: 3.5.5`。
- Dependabot 仅开 **security** 更新，不开常规版本更新。
- 新增依赖前先问：能否用现有能力实现？M0 已因此砍掉 7 个包（见第 5 节）。
