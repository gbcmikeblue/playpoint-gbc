# 环境搭建实录（M0 实况）

> 记录**实际**装了什么、踩了什么坑、与规划文档的偏差。后续接手的人只看这一篇就能复现环境。
> 规划文档见同目录 `03-依赖与版本清单.md`（本文以实际为准，规划为准的部分会标注）。

## 1. 最终环境

| 组件 | 实际版本 | 说明 |
| --- | --- | --- |
| Node.js | **20.11.1** | 通过 nvm-windows 安装；全局默认仍是 16.15.1，**每条命令需先加载 `.work/env.ps1`** |
| npm | 10.2.4 | 随 Node 20 |
| 容器 | **Podman 5.8.3**（WSL 后端） | 本机原本没有 Docker（Windows 与 WSL 均无），改用 Podman |
| WSL | 3.0.3.0 / 内核 6.18.54 | 原本 2.0.14，Podman 起不来，`wsl --update` 升级后正常 |
| PostgreSQL | 15-alpine（容器 `playpoint-pg`） | 端口 5432，库/用户/密码均为 `playpoint` |
| Redis | 7-alpine（容器 `playpoint-redis`） | 端口 6379（M0 代码暂未使用） |
| 镜像源 | `docker.m.daocloud.io` | `docker.io` 直连被拒（connection refused） |
| 小程序 | 原生 + TS，基础库 3.5.5 | 开发者工具已装 |

## 2. 目录与脚本

```
playpoint-gbc/
├── .work/                     ← 工具脚本与日志（不提交产物）
│   ├── env.ps1                统一环境引导：把 Node20 / Podman 加进 PATH
│   ├── start-api.ps1          后台启动后端，日志写 api.log
│   └── api.log                后端运行日志
├── backend/                    NestJS + Prisma
└── miniprogram/                小程序
```

**每条 PowerShell 命令前都要加载环境**（因为 nvm 的全局软链仍指向 Node 16）：

```powershell
. D:\project\playpoint-gbc\.work\env.ps1
node -v      # v20.11.1
podman ps    # playpoint-pg / playpoint-redis
```

## 3. 启动 / 停止

```powershell
# 0) 环境
. D:\project\playpoint-gbc\.work\env.ps1

# 1) 容器（Podman 虚拟机关机后需先 start）
podman machine start
podman start playpoint-pg
podman start playpoint-redis

# 2) 后端（端口 3000）
cd D:\project\playpoint-gbc\backend
npx ts-node -T src/main.ts          # 前台；或
Start-Process powershell -ArgumentList '-NoProfile','-File','D:\project\playpoint-gbc\.work\start-api.ps1' -WindowStyle Hidden

# 3) 小程序
# 用微信开发者工具打开 D:\project\playpoint-gbc\miniprogram
# 详情 → 本地设置 → 勾选「不校验合法域名」（因为请求 http://localhost:3000）
```

**验证**：

```powershell
curl http://localhost:3000/api/v1/app/config
curl http://localhost:3000/api/v1/home/feed?city=shenzhen
# Swagger: http://localhost:3000/docs
```

## 4. 踩坑记录（按发生顺序）

| # | 问题 | 现象 | 解决 |
| --- | --- | --- | --- |
| 1 | Node 版本过低 | 全局是 16.15.1，NestJS 10 / Prisma 5 要求 ≥18 | `nvm install 20.11.1`；`nvm use` 因符号链接权限未生效，改为在 `env.ps1` 里把 `%APPDATA%\nvm\v20.11.1` 前置进 PATH |
| 2 | 本机没有 Docker | `docker` 命令不存在，无 Docker Desktop，WSL 内也无 | 按需求改 Podman |
| 3 | winget 装 Podman 失败 | `0x8a15005e 服务器证书与任何预期值都不匹配`（msstore 源） | 指定 `--source winget`；最终改为直接下 GitHub 的 `podman-installer-windows-amd64.msi` 静默安装 |
| 4 | Podman machine 起不来 | `machine did not transition into running state: ssh error` | WSL 2.0.14 太旧，`wsl --update` 升到 3.0.3 + `wsl --shutdown` 后正常 |
| 5 | 镜像拉取被拒 | `dial tcp 108.160.167.165:443: connection refused` | 镜像前缀换 `docker.m.daocloud.io` |
| 6 | 后端启动崩溃 | Swagger 报 `Cannot read properties of undefined (reading '0')` | **`tsx`(esbuild) 不支持 `emitDecoratorMetadata`**，Nest 拿不到构造参数类型。改用 `ts-node -T` |
| 7 | 小程序 `npx tsc` 报错 | 提示 "This is not the tsc command you are looking for" | miniprogram 没装 typescript，补装后正常 |
| 8 | `wx.request` 的 method 类型不含 PATCH | TS2322 | 断言为 any（运行时支持） |

## 5. 与规划文档的偏差（以实际为准）

| 规划 | 实际 | 原因 |
| --- | --- | --- |
| 后端 dev 用 `tsx watch` | **`ts-node -T`** | tsx 不支持装饰器元数据，Nest 无法启动 |
| Docker + docker-compose | **Podman + 单容器命令** | 本机无 Docker；compose 需要额外插件，M0 只有两个容器 |
| 状态管理用 `mobx-miniprogram` | **自写 40 行 `createStore`** | 小程序 npm 构建在 M0 增加不确定性；自写零依赖，后续要换 mobx 只改 `stores/store.ts` |
| 10 个 base 组件 | **7 个**（nav-bar / privacy-modal / skeleton / empty / tag / avatar / badge） | 按钮、胶囊、卡片用 `mixins.wxss` 的 class 即可；`sheet`/`cell` 在 M1 用到时再抽 |
| 主包 + 6 分包 | **M0 只注册主包 5 页** | 分包页面尚未实现，提前注册会编译报错；M1 逐页加 |
| `postgres:15` | **`15-alpine`** | 体积小一半，行为一致 |
