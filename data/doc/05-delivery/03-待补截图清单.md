## 4. 支付相关（不用截，方案已改为自研）

既然**不接微信支付**，收银台由我们自绘，不需要参考图。计划如下（已写入产品/前端/后端文档）：

```
报名/参加（价格 > 0）
  → 创建订单 POST /orders
  → 跳转收银台 pkg-activity/pages/pay/index
       · 订单摘要（活动封面/标题/场次）
       · 金额（大写 + 数字）
       · 支付方式：微信支付（模拟）单选，默认勾选
       · 15 分钟倒计时
       · 底部「立即支付 ¥xx」
  → 点击后本地 loading 1.5s → POST /orders/:id/mock-pay
  → 支付成功页（票已入票夹 / 查看票）
价格 = 0 → 直接报名成功，跳过收银台。
```

- 后端只落 `pay_order` 表与状态机，**不依赖微信商户号、不签名、不对账**，纯模拟回调。
- 目的是把「订单 → 支付 → 票 → 核销」的完整流程跑通，方便以后替换真实支付。

## 5. 补图后的处理流程（我这边）

1. 写一个一次性脚本，把 `batch2/` 里所有图缩到**宽 560**（约 780 token/张，比首轮 433 略高，因为这次要靠文字细节）；
2. **只读一次**，逐图结论追加进 `99-evidence/01-截图识图记录.md`；
3. 同步修订 `02-design/02-页面排版规格.md` 对应页、`01-product/02-页面清单`、`04-backend/02-数据模型` 中"待确认"的字段；
4. 缩放后的临时图与脚本用完即删，原图保留在 `batch2/`。

**成本预估**：若 14 张全补，560 宽约 780 token/张 ≈ **11k token**；若只补 A 类 6 张 ≈ 4.7k token。
