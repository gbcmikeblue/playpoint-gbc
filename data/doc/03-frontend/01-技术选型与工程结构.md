# 前端技术选型与工程结构

## 1. 选型结论

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **微信原生小程序 + TypeScript** | 本项目重度依赖自定义 tabBar（中间凸起 FAB）、沉浸式导航、手势弹层、滚动位置控制；跨端框架（Taro/uni-app）在这些点上调试成本高于收益，且无 H5/App 需求 |
| 语言 | TypeScript（`useCompilerPlugins: ["typescript"]`） | 接口契约多、字段多，类型是最便宜的防错手段 |
| 状态管理 | **自写 `stores/store.ts`（约 40 行）** | 不装 mobx：引入它就要走小程序 npm 构建，给环境加不确定性；自写 store 零依赖、零构建，API 仍是 `createStore/set/subscribe`，将来要换只改这一个文件 |
| 样式 | WXSS + CSS 变量 + 可选 Sass | 设计令牌集中在 `styles/variables.wxss`，配合 `--c-brand` 等变量 |
| UI 基础 | **自建 base 层**（见组件库清单） | 视觉高度定制（荧光绿 + IP 插画），引入 TDesign 反而要大量覆盖；仅日期/地区等使用原生 `picker` |
| 请求 | 自封装 `request.ts`（拦截器 + 重试 + 并发控制） | 需要统一注入 token、错误提示、401 静默续期 |
| 构建 | 微信开发者工具 + `miniprogram-ci`（CI 上传） | 标准链路 |
| 监控 | `wx.reportPerformance` + 自建错误上报 `/api/v1/track` | 首屏、请求失败率 |

### 备选方案（不推荐，记录备查）
- **Taro 3 + React**：适合未来要多端时切换；代价是自定义 tabBar/纹理动效坑多。
- **云开发（CloudBase）**：能省后端，但打卡定位、榜单排序、后台运营配置会受限，且后期迁出成本高。

## 3. 环境与配置

| 环境 | baseURL | 用途 |
| --- | --- | --- |
| dev | `https://dev-api.playpoint.xx/api/v1` | 本地联调（需在开发者工具关闭域名校验） |
| test | `https://test-api.playpoint.xx/api/v1` | 体验版 |
| prod | `https://api.playpoint.xx/api/v1` | 正式 |

- `config/env.ts` 通过 `__wxConfig.envVersion` 自动切换，禁止把环境判断散落在业务代码。
- 合法域名需在小程序后台配置 `request` / `uploadFile` / `downloadFile`。
- 版本号（个人资料页 `v5.5.8`）读 `getAppConfig()` 返回的 `version`，与后端发布版本对齐。

## 4. 关键基础能力

### 4.1 `request.ts`
- 统一 baseURL、超时 10s、`Authorization: Bearer <token>`。
- 响应契约：`{ code: 0, data, message }`；`code !== 0` 抛业务错误并 toast（可 `silent` 关闭）。
- 401 → 触发单例续期（并发请求排队），失败则跳授权并清空 store。
- GET 去重（同 URL 进行中请求复用）、写请求 3s 内相同 payload 去重（防连点重复报名）。

### 4.2 登录态
```
app.onLaunch
  → getPrivacySetting / 本地版本比对 → 决定是否弹 P12
  → wx.login → POST /auth/login {code, scene} → {token, user, isNew}
  → store.user.set(...) → 首屏渲染
```
- token 存 storage（`cm_token`），有效期 7 天，静默续期接口 `/auth/refresh`。
- 昵称头像不再依赖 `wx.getUserProfile`（已废弃），改为用户自填（与截图一致：报名时"取个响亮的名字"）。

### 4.3 定位
- `wx.getFuzzyLocation`（需在 `app.json` 声明 `requiredPrivateInfos`）拿城市级坐标，仅用于城市/距离，不落库原始经纬度。
- 拒绝授权 → 用 `city` 缓存或默认城市，UI 不报错，仅在切换城市时提示去设置页开启。

### 4.4 图片上传
- 先 `wx.compressImage`（质量 80、长边 1600）→ `wx.uploadFile` → 后端返回 `fileId + url`。
- 头像做 1:1 裁剪：用 `image-cropper` 自研组件或 `wx.cropImage`（基础库 ≥2.26）。
- 失败重试 2 次，超 10MB 直接拦截。

## 5. 性能预算

| 指标 | 目标 |
| --- | --- |
| 主包体积 | ≤ 1.5MB（不含分包） |
| 首页首屏（启动到可交互） | ≤ 1.8s（4G） |
| 首页接口数 | ≤ 2（聚合 `/home/feed` 返回 banner+分类+列表） |
| 图片 | 列表图 ≤ 60KB，统一 WebP + CDN 缩放参数 |
| 长列表 | 分页 20，超过 200 条用 `recycle-view` 或分页堆叠 |
| setData | 单次 payload < 64KB，禁止整体列表 setData |

## 6. 优化要点（提前设计，避免返工）

1. **接口聚合**：首页把 banner、分类、feed 合成一次请求，减少 3 次 RTT。
2. **分包预下载**：进入首页后 `preloadRule` 预下载 `campaign` 包（用户大概率点打卡）。
3. **骨架屏**：列表首屏用骨架，不用 loading 遮罩。
4. **图片占位**：`aspectFill` + 主色占位块，避免抖动。
5. **tabBar 状态**：自定义 tabBar 用 `getTabBar().setData({selected})`，避免整页刷新。
6. **滚动位置**：我的页内 Tab 切换用 `hidden` 而非销毁，保住滚动位置（截图要求）。

## 7. 编码规范

- 文件命名 kebab-case；组件 `index.ts` 统一导出。
- 事件命名 `onXxx`，对外暴露 `bind:xxx`。
- 所有页面 `onLoad` 只取参数 + 拉数据，业务编排放 `services`。
- 禁止 `any`（除第三方类型缺失处，需 `// @ts-expect-error` 注明原因）。
- 提交前跑 `eslint` + `tsc --noEmit`，CI 阻断。
