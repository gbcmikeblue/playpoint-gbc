# 状态管理与数据流

## 1. 分层原则

```
页面(page) ──调用──> service ──> request ──> API
    │                   │
    └──只读/写──> store ─┘（需要跨页共享的状态才进 store）
```

- **页面私有状态**（列表数据、滚动位置、表单草稿）留在 `data`，不进 store。
- **跨页共享状态**（登录用户、城市、未读数、隐私同意、选中的兴趣天梯）进 store。
- service 不做状态写入，由调用方决定；唯一例外是 `auth.ts`（登录成功后写 user store）。

## 2. store 划分

| store | 职责 | 关键状态 |
| --- | --- | --- |
| `user` | 登录态与用户档案 | `token / profile / mbti / ladders / stats` |
| `app` | 全局上下文 | `city / config / privacyVersion / agreed / systemInfo / navHeight` |
| `message` | 未读与角标 | `unreadTotal / conversations` |
| `ui` | 全局 UI 态 | `signupSheet / mbtiSheet / toast / syncScrolling` |

### 2.1 数据结构（TS）

interface UserProfile {

## 3. 绑定方式

```ts
// stores/store.ts —— 自写，约 40 行，零依赖
const appStore = createStore({ user: null, city: { code: 'shenzhen' }, ready: false })

// 页面里：把需要的字段自动同步到 data
Page({
  data: { user: null, city: null },
  onLoad() {
    bindStore(this, appStore, ['user', 'city'])   // 首次同步 + 订阅后续变更
  },
})

// 写操作只暴露语义化方法，页面不直接 set
setCity({ code: 'shanghai', name: '上海市' })
```
- 只用 `bindStore` 做单向渲染，写操作走 `stores/` 导出的方法，页面不直接改 state。
- 高频变化字段（如输入框）**不要**放 store，否则触发全页 setData。
- 订阅在 `onUnload` 自动解绑（`bindStore` 内部接管 `onUnload`）。

## 4. 核心数据流

### 4.1 启动与隐私
```
onLaunch
 ├─ 读 storage: cm_token, cm_privacy_agreed_at, cm_city
 ├─ GET /app/config  → app.setConfig（协议版本从这里来）
 ├─ privacyAgreed = (本地版本 === config.agreementVersion)
 └─ 若未同意 → 首页 onShow 弹 privacy-modal，阻断滚动与 tabBar 点击
```
- 同意后：`POST /app/privacy-consent { version }` + 写 storage（存版本号而非布尔值，协议升级可重新弹）。

### 4.2 首页 feed
```
onLoad  → GET /home/feed?city=&category=&sort=&cursor=
onPullDownRefresh → 重置 cursor，重拉
onReachBottom → 用 cursor 追加（append 到 data.list 尾部，setData 只传新增段）
切换分类/排序 → 清空 list + cursor=0，缓存最近 3 个分类的首页数据（内存 Map，5 分钟内有效）
```
- 排序/筛选条件写 storage，下次进入恢复。
- 活动卡点击 → `nav.toActivity(id)`，同时把当前 list 快照写 `activityStore`（详情首屏用它做骨架，避免白屏）。

### 4.3 报名与模拟支付
```
[P03 详情] 点击 action-bar
 → 检查登录（无 → 登录）
 → 检查是否已报名（GET /campaigns/:id/signup-status）
   ├─ 已报名 → 直接跳到票夹/打卡
   └─ 未报名 → ui.openSignupSheet({ campaignId, priceCent })
[P04 弹层] 提交
 → 校验（昵称 1-20、性别必选）
 → 预签名上传头像（如有）→ fileId
 → POST /campaigns/:id/signups { nickname, gender, avatarUrl }
      ├─ priceCent = 0  → { signupId, ticketId }  → 直接成功
      └─ priceCent > 0  → { orderId, expireAt }   → navigateTo 收银台
 → 成功：关弹层 → toast → 票夹角标刷新 → 详情按钮切"立即打卡"
 → 失败 409（重复报名）：按已报名处理，不展示错误
```

### 4.3.1 收银台（`pkg-activity/pages/pay/index`）
```
onLoad({orderId})
 → GET /orders/:id  → 渲染订单摘要 + 金额 + expireAt
 → 起本地倒计时（与 expireAt 对齐，每秒刷新；归零则置灰并提示"订单已过期"）
点「立即支付」
 → 按钮 loading（1.5s 视觉停留）→ POST /orders/:id/mock-pay
   ├─ 成功 → redirectTo pay-result?status=success
   └─ 失败 → loading 结束、toast、可重试（订单状态由后端保证幂等）
返回/关闭 → 订单保持"待支付"，票夹或我的页可继续支付或取消
```
- 收银台为**自绘**，无参考截图；不做真实支付、不做退款与对账。
- 金额只读，禁止前端改价；`amountCent` 一律以后端返回为准。

### 4.4 打卡提交
```
拍照/选图 → 压缩 → 上传 → 获取当前定位（gcj02）
→ POST /campaigns/:id/checkins { checkpointId, fileIds, location, content }
→ 后端校验距离（≤300m）与频次（每点每日 1 次）
→ 返回 { progress, newMedals[] }
→ 有新奖牌 → 全屏奖牌动画 + 写 user.medals
```

### 4.5 消息
```
消息 Tab onShow → GET /conversations?cursor= → message.setConversations
进入聊天 → GET /conversations/:id/messages?before=&limit=20
发送 → 本地乐观插入（status: sending）→ POST → 回填 messageId/status
轮询：聊天页 5s 轮询新消息（MVP 不用 WebSocket；后续可切 wx.connectSocket）
未读：tabBar 角标 = message.unreadTotal，进入会话后清零并上报已读
```

### 4.6 兴趣天梯 / MBTI
```
P07 点击运动 → nav.toQuiz(sport)
P08 答题 → 本地 draft（每题一个 value，存 storage 防退出丢失）
       → 全部答完启用"生成"
       → POST /ladder/submit { sport, answers[] } → { level, goodAt[] }
       → redirectTo 结果页 → user.ladders 更新 → 返回我的页刷新卡片
MBTI → mbti-sheet 选择 → PATCH /users/me { mbti } → 清除 hasNewMbti
```

## 5. 缓存策略

| 数据 | 位置 | 失效 |
| --- | --- | --- |
| token | storage | 7 天 / 401 |
| 城市 | storage | 手动切换 |
| 分类与配置 | storage + 内存 | 启动时对比 `config.version` |
| 报名信息草稿 | storage | 提交成功 |
| 首页 feed | 内存 Map（3 分类 × 5 分钟） | 下拉刷新 / 超时 |
| 用户档案 | store + storage | 每次进入我的页静默刷新 |
| 图片 | 小程序本地缓存（系统管理） | 自动 |

## 6. 错误与降级

| 场景 | 处理 |
| --- | --- |
| 网络失败 | 列表展示错误态 + "重新加载"；已缓存数据继续展示并顶部提示"网络不佳" |
| 401 | 静默续期，失败跳授权页，保留 `redirect` 参数回跳 |
| 403（未报名访问打卡） | toast + 跳详情页 |
| 429（频控） | toast"操作太频繁，请稍后" |
| 图片上传失败 | 单图重试按钮，不阻塞整表单 |
| 接口超时 | 8s 超时，重试 1 次（仅 GET） |

## 7. 埋点

统一 `track(event, params)`，批量上报（10 条或 5s flush），字段：`event, page, uid, ts, params`。

必备事件：`page_view`、`banner_click`、`category_switch`、`activity_click`、`signup_submit/success/fail`、`checkin_submit`、`medal_gain`、`mbti_select`、`ladder_submit`、`msg_send`、`share`。
