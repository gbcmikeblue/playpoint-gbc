# 后端架构与技术选型

## 1. 选型结论

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | Node.js 20 LTS | 与前端同语言，JSON 接口为主，团队成本低 |
| 框架 | **NestJS 10** | 模块化清晰，DTO 校验（class-validator）、Swagger 自动生成，适合多人协作 |
| 语言 | TypeScript | 与前端共享类型定义（`services/types` 可由 OpenAPI 生成） |
| 数据库 | **PostgreSQL 15** | 需要 JSONB（活动报名表配置、打卡点坐标）与 PostGIS 地理查询（附近活动、打卡半径） |
| 缓存 | Redis 7 | 榜单 ZSET、会话未读、频控、首页聚合缓存 |
| 对象存储 | 腾讯云 COS / 阿里云 OSS | 图片上传、CDN 加速；小程序上传走临时密钥（STS） |
| 搜索 | PG `pg_trgm` + `tsvector`（MVP） | 活动/俱乐部名称模糊搜索够用；量级上来再上 ES |
| 消息 | 站内信（DB）+ 长轮询；后续可选 WebSocket | MVP 聊天低频，5s 轮询足够 |
| 鉴权 | JWT（HS256，7 天）+ refresh token | 小程序场景简单可靠；管理端另用 RBAC |
| 支付 | **模拟支付（Mock）**，不接微信支付 | 练手项目只跑通「下单 → 支付 → 出票 → 核销」；接口以 `mock` 命名，后期替换真实网关只改实现 |
| 部署 | **Podman** + Nginx + 1 台 4C8G（起步） | 开发机无 Docker，统一用 Podman（WSL 后端）；生产可用任意 OCI 运行时 |
| 可观测 | Pino 结构化日志 + Sentry + `/health` | 错误定位快 |

### 备选：微信云开发（CloudBase）
- 优点：免运维、免鉴权、图片直传。
- 缺点：定时任务与榜单类聚合查询弱、后台运营配置受限、迁移成本高。
- **结论**：不采用，但保留「对象存储 + 云函数做图片处理」的混合可能。

## 2. 整体架构

```
微信小程序
   │ HTTPS
   ▼
Nginx (TLS, gzip, 限流)
   │
   ▼
NestJS API (无状态, 可水平扩)
   ├── AuthModule        微信登录、JWT、刷新
   ├── AppModule         配置、城市、分类、协议、埋点
   ├── HomeModule        首页聚合 feed、Banner、广告位
   ├── ActivityModule    活动 CRUD、报名、票
   ├── OrderModule      （模拟）下单、支付、关单
   ├── CampaignModule    挑战赛、打卡点、打卡、榜单、奖牌
   ├── UserModule        档案、MBTI、兴趣天梯、标签、关注
   ├── MessageModule     会话、消息、通知
   └── AdminModule       运营后台接口（RBAC）
   │
   ├── PostgreSQL（主库）
   ├── Redis（缓存/榜单/频控）
   └── COS（对象存储 + CDN）
```

### 分层约定
```
Controller（校验 + 鉴权 + 组装 DTO）
  → Service（业务规则，事务边界）
    → Repository / Prisma（数据访问）
```
- 所有写操作走事务；报名、打卡这类涉及计数与奖牌的用 `SELECT ... FOR UPDATE` 或唯一索引兜底。
- 领域事件用轻量 `EventEmitter2`（报名成功 → 发票、加计数、发消息），不引入 MQ。

## 3. 关键非功能设计

| 关注点 | 方案 |
| --- | --- |
| 幂等 | 报名：`UNIQUE(campaign_id, user_id)`；打卡：`UNIQUE(checkpoint_id, user_id, date)`；写接口支持 `Idempotency-Key` 头 |
| 频控 | Redis 滑动窗口：打卡 10 次/分钟、报名 20 次/分钟、发消息 30 次/分钟 |
| 鉴权 | 全局 `JwtGuard`，`@Public()` 放行登录/配置/首页；管理端 `@Roles('admin')` |
| 上传安全 | 服务端签发 STS 临时密钥（10 分钟），限制 `image/*`、≤10MB；回调校验真实 mime |
| 敏感数据 | 手机号 AES 加密存储，接口统一脱敏（`138****8888`）；不存原始经纬度，只存城市/POI |
| 合规 | 隐私版本表 + 用户同意记录（IP、UA、时间）；注销账号支持 30 天软删 |
| 时区 | 全库 `timestamptz`，业务按 `Asia/Shanghai` 计算"今天" |
| 分页 | 游标（`cursor` + `limit`），不用 offset，避免翻页抖动 |
| 缓存 | 首页 feed 60s；榜单实时（ZSET）；配置 5 分钟；缓存穿透用空值占位 |

## 4. 环境与部署

| 环境 | 域名 | 数据库 | 说明 |
| --- | --- | --- | --- |
| dev | dev-api.playpoint.xx | localhost:5432 | 开发者工具需关闭域名校验 |
| test | test-api.playpoint.xx | 独立实例 | 体验版使用 |
| prod | api.playpoint.xx | 主库 + 每日快照 | 必须 HTTPS + 备案域名 |

```powershell
# 开发机：Podman（WSL 后端），两容器直接命令管理，不引 compose
podman machine start
podman run -d --name playpoint-pg --restart unless-stopped -p 5432:5432 `
  -e POSTGRES_USER=playpoint -e POSTGRES_PASSWORD=playpoint -e POSTGRES_DB=playpoint `
  docker.m.daocloud.io/library/postgres:15-alpine
podman run -d --name playpoint-redis --restart unless-stopped -p 6379:6379 `
  docker.m.daocloud.io/library/redis:7-alpine

# 应用（本机直跑；生产再容器化）
cd backend
npm run dev      # ts-node -T src/main.ts  → :3000
```

> 生产环境用任意 OCI 运行时（Podman/Docker 皆可）+ Nginx；镜像源与 `DATABASE_URL` 通过环境变量注入，不改代码。

- CI：push → `tsc` + `eslint` + 单测 → 构建镜像 → 部署 test；手动审批后 prod。
- 备份：每日全量 + WAL 归档；保留 7 天。
- 监控：`/health`（DB/Redis 连通）、慢查询日志 >200ms 告警、5xx 率 >1% 告警。

## 5. 后台管理（P1）

- 技术：`Vue3 + Element Plus` 或直接用 `NestJS + React-Admin`；与 API 同域，走 `/admin`。
- 必备模块：Banner/分类排序、挑战赛与打卡点配置、奖牌规则、活动审核、用户与报名查询、内容举报处理、协议版本发布。
- 权限：`admin` / `operator` / `auditor` 三角色，操作留审计日志。

## 6. 与前端契约约定

1. 统一响应：`{ code: 0, message: "ok", data: {...}, traceId }`；`code !== 0` 为业务错误。
2. 错误码段位：`1xxx` 通用、`2xxx` 认证、`3xxx` 活动/报名、`4xxx` 打卡、`5xxx` 用户、`6xxx` 消息。
3. 时间统一 ISO8601 字符串（`2026-10-18T18:00:00+08:00`）。
4. ID 用 `string`（雪花 ID 或 UUID），避免 JS 精度丢失。
5. 金额单位「分」，字段名 `priceCent` / `amountCent`；前端只读展示，禁止本地改价。
6. OpenAPI 由 NestJS Swagger 生成，前端 `openapi-typescript` 生成 `services/types`，保证类型同步。
