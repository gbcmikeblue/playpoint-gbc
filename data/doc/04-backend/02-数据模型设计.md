# 数据模型设计

数据库：PostgreSQL 15。主键统一 `id varchar(32)`（雪花 ID），时间 `timestamptz`，软删 `deleted_at`，金额单位分（`*_cent`）。

## 1. ER 关系概览

```
user ──1:N── user_sport_ladder ──1:N── ladder_answer
  │
  ├──1:N── privacy_consent
  ├──1:N── activity_signup ──1:1── ticket
  ├──1:N── campaign_signup ──1:N── checkin
  ├──1:N── user_medal ──N:1── medal
  ├──N:M── club（club_member）
  └──N:M── conversation（conversation_member）──1:N── message

city ──1:N── activity
category ──N:M── activity（activity_category）
campaign ──1:N── campaign_checkpoint
campaign ──1:N── campaign_reward（奖牌规则）
activity ──N:1── host(user) / club
banner / ad_slot / notice ── 运营内容
```

## 3. 内容域

### 3.1 `city`

`id, code, name, province, lat, lng, is_hot, sort, status`
索引：`UNIQUE(code)`、`idx(is_hot, sort)`。

### 3.2 `category`（首页分类胶囊）

`id, name, icon, emoji, sort, is_hot, status`

| city_id | varchar(32) | |
| description | text | 长描述 |

索引：`idx(city_id, status, start_at)`。

### 4.2 `campaign_checkpoint`（打卡点）

`id, campaign_id, name, poi_name, address, lat, lng, radius_m(默认300), sort, cover_url, intro, description, status`
- `intro` = 打卡点介绍长文（如"游客集合地点，由此可乘车前往灵山幻境景点"）。
- 距离不落库，按请求时的用户坐标实时计算并返回 `distanceText`（前端不换算单位）。
索引：`idx(campaign_id, sort)`。

### 4.3 `campaign_signup`

`id, campaign_id, user_id, nickname, gender, avatar_url, status[0已报名/1已通关/2已取消], finished_at, duration_sec, created_at`
- `UNIQUE(campaign_id, user_id)`。
- `duration_sec` 用于「通关用时榜」，榜单用 Redis ZSET `rank:campaign:{id}`（score = duration_sec）。

### 4.4 `checkin`（打卡记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | varchar(32) | PK |
| campaign_id / checkpoint_id / user_id | | |
| images | jsonb | 最多 9 张 |
| content | varchar(300) | 打卡文案 |
| lat / lng | numeric | 提交时定位 |
| distance_m | int | 与打卡点距离，服务端计算 |
| status | smallint | 0 待审核 / 1 通过 / 2 驳回 |
| checkin_date | date | 用于「每点每日 1 次」唯一约束 |
| created_at | | |

约束：`UNIQUE(checkpoint_id, user_id, checkin_date)`；索引 `idx(campaign_id, user_id)`。

### 4.5 `medal` / `user_medal`

- `medal(id, name, icon_url, description, type[打卡/活动/成就], campaign_id?, rule jsonb, status)`
- `user_medal(id, user_id, medal_id, source_type, source_id, created_at)`，`UNIQUE(user_id, medal_id, source_id)`。
- 发放规则放 `rule jsonb`：`{ "type":"checkin_all", "count":5 }` / `{ "type":"first_finish", "rank_lte":100 }`。

## 5. 社交与消息域

### 5.1 `club` / `club_member`

`club(id, name, logo_url, city_id, owner_id, member_count, description, status, created_at)`
`club_member(club_id, user_id, role[0成员/1管理/9创建者], joined_at)`，PK `(club_id,user_id)`。

### 5.2 `conversation` / `conversation_member` / `message`

| 表 | 关键字段 |
| --- | --- |
| `conversation` | `id, type[1单聊/2群聊/9系统], title, avatar_url, last_msg_at, last_msg_digest, member_count` |
| `conversation_member` | `conversation_id, user_id, unread_count, last_read_at, muted`，PK 复合 |
| `message` | `id, conversation_id, sender_id, type[1文本/2图片/3表情/9系统], content, extra jsonb, created_at, revoked_at` |

索引：`idx(conversation_id, created_at DESC)`、`idx(sender_id)`。
- 列表摘要：非文本存 `[图片]`/`[自定义消息]` 到 `conversation.last_msg_digest`，避免联表取正文。
- 未读：`conversation_member.unread_count` + Redis `unread:{uid}` 汇总给 tabBar。

### 5.3 `notice`（通知消息）

`id, user_id(nullable=广播), event_type[pay_success/pay_timeout/signup_success/checkin_medal/system], biz_title, thumb_url, title, content, ref_type, ref_id, read_at, created_at`
- `biz_title` = 通知卡上段灰色业务名（"【深圳市】探索易经智慧，每周都有课"），随业务对象快照存储。
- `title` = 加粗事件标题（"支付成功"），`content` = 正文（"你已成功支付，可以邀请朋友一起玩"）。
- 支付流程至少产出两类通知：**支付成功**、**15 分钟内未支付提醒**。
索引：`idx(user_id, read_at, created_at DESC)`、`idx(event_type, created_at)`。

> 搜索历史不落库：存本地 `storage`（`cm_search_history`，最多 10 条），避免为一个弱需求建表；需要跨端同步时再补表。

## 7. 关键业务规则（服务层）

| 规则 | 实现 |
| --- | --- |
| 报名幂等 | 唯一索引 + 捕获 `23505` 转业务成功 |
| 名额控制 | `UPDATE activity SET joined_count=joined_count+1 WHERE id=? AND joined_count<capacity` 影响行数判断 |
| 0 元直通 | `amount_cent = 0` 时不建订单，signup 直接置 1 并出票 |
| 下单幂等 | 同一 `(biz_type, biz_id, user_id)` 存在待支付单时直接复用，不新建；可用 `Idempotency-Key` 二次校验 |
| 支付成功（mock） | 事务内：`pay_order.status=1, paid_at=now()` → `signup.status=1` → `joined_count+1` → 出票；重复调用返回已支付结果（幂等） |
| 超时关单 | 每分钟扫 `status=0 AND expire_at<now()` → 置 3 → 释放名额；前端倒计时归零后不可再支付 |
| 打卡距离 | Haversine 计算 `distance_m`，`> radius_m` 直接拒绝（4001） |
| 打卡频次 | 唯一索引 + Redis 频控双保险 |
| 通关判定 | 打卡点数 == 有效打卡点数 → 置 `status=1`、记 `duration_sec`、写 ZSET、触发奖牌 |
| 奖牌幂等 | `UNIQUE(user_id, medal_id, source_id)` |
| 未读汇总 | 读 Redis `unread:{uid}`，DB 为准定时回填 |
| 用户注销 | `status=2` + `deleted_at=now()+30d`，期满物理删/匿名化 |
